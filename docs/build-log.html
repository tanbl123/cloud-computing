5.1 Worth writing up in the report

How the application resolves its credentials. The app copies the APP_DB_* environment variables into its config synchronously, then asynchronously fetches Mydbsecret and overwrites them. The secret always wins, so passing database settings on the command line achieves nothing. If the lookup fails it falls back to localhost with nodeapp and student12, which is exactly what the phase-2 user data builds locally.

The consequence is that whether an instance uses local MySQL or RDS is decided solely by whether it has an IAM role. The phase-2 POC is launched with no instance profile so the lookup fails and it uses its own database. The App Server gets LabInstanceProfile, reads the secret, and connects to RDS. That single difference is the whole decoupling story, and it is the answer to "how does the decoupling actually work" in the demonstration.

Diagnostic: grep -n "Secrets not found" /home/ubuntu/app.log. Present means local MySQL, absent means it read the secret and is on RDS.

Why the database route table has no default route. Defence in depth beyond the security groups: even a misconfigured group cannot give the database a path to the internet.

Every lab restriction that forced a substitution. S3 instead of CloudWatch for flow logs, no WAF, single-AZ RDS. Naming the constraint and the production alternative reads as understanding rather than excuse-making.

7.1 Required scope versus enhancements

The AWS project brief lists what the solution must do. Two things in our runbook go beyond it, and it is worth knowing which is which before the budget gets tight.

Required: the VPC and subnets, the EC2 web tier, RDS MySQL in private subnets, Secrets Manager for the credentials, Cloud9, the Application Load Balancer across two AZs, EC2 Auto Scaling with a target tracking policy, the load test, the architecture diagram and the cost estimate. That is stages 01 to 14, 16 and 17.

Beyond the required scope: VPC flow logs at stage 15, and the WAF and Shield entries on the diagram. The brief invites extra work, saying you are encouraged to implement additional functionality, so these earn credit as security evidence rather than being wasted effort. We are building it.
